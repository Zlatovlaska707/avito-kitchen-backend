# ADR-0006: Одна активная корзина на покупателя

## Контекст

В маркетплейсе легко представить корзину «пицца из одного места, роллы из другого». На кухне такой заказ не существует: готовят в разных заведениях, с разными минимумами чека, зонами и временем. Мультизаведенческий чекаут — отдельный домен со split-оплатой, несколькими ETA и несколькими курьерами.

Для MVP это избыточно: показать, как человек находит блюдо и оформляет доставку из одного ресторана.

## Решение

У покупателя не больше одной корзины в статусе `active`. Это не только договорённость кода: partial unique index `carts_one_active_per_customer_idx ON carts (customer_id) WHERE status = 'active'`.

Корзина всегда привязана к одному `venue_id`. Попытка положить позицию из другого заведения отвечает `409 cart_venue_mismatch`. Клиент либо очищает корзину, либо заканчивает текущий заказ.

Одинаковые блюда с одинаковым набором опций схлопываются по `options_hash`, чтобы не плодить строки.

## Следствия

Пересчёт итогов и checkout линейные: нет merge двух прайсов и двух зон доставки. Инвариант нельзя обойти гонкой двух `POST /cart/items` — его держит индекс.

Нельзя собрать «комбо из двух ресторанов» в одном окне оплаты. Для текущей платформы это честный и понятный отказ, а не молчаливая порча данных...

Если продукт дорастёт до маркетплейс-корзины, модель скорее будет parent order плюс sub-order на заведение, а не «одна корзина со смешанными строками».
